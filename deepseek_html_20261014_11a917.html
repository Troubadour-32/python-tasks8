0 Введение: как вообще работает сайт

Что такое веб-приложение?
Это программа, работающая на сервере, которая принимает HTTP-запросы от браузера и возвращает HTTP-ответы. Браузер = клиент. Сервер = то, где работает твой код.

0.1. Что происходит, когда ты открываешь сайт

  1. Ты вводишь адрес http://127.0.0.1:5000/test в браузер.
  2. Браузер отправляет HTTP-запрос методом GET на этот адрес.
  3. Flask-сервер получает запрос и смотрит: «у меня есть маршрут /test?»
  4. Находит функцию test(), вызывает её.
  5. Функция читает из БД следующий вопрос, собирает HTML через шаблон и возвращает его.
  6. Сервер отправляет HTML обратно браузеру как HTTP-ответ.
  7. Браузер рисует страницу.
Ресторан: ты (браузер) делаешь заказ официанту (Flask). Официант идёт на кухню (БД), берёт блюдо, оформляет на тарелке (шаблон) и приносит тебе.

0.2. HTTP-методы: GET и POST

HTTP — язык общения браузера и сервера. У каждого запроса есть метод. Два главных для нас:
  • GET — «дай мне страницу». Данные передаются прямо в URL. Ничего не меняет.
  • POST — «прими данные». Данные передаются в теле запроса. Меняет состояние.
Что делаетМетодПример
Открыть страницуGETТы заходишь на /test
Отправить формуPOSTТы нажал «Хочу комедию»
Отправлять данные формы методом GET. Пароль окажется в адресной строке и в истории браузера.

0.3. Что такое Flask

Flask — это «микрофреймворк» для Python. «Микро» — потому что он даёт только самое необходимое, а остальное подключается по желанию. Задача Flask — связать URL с функцией Python и вернуть браузеру ответ.
Мы берём Flask, а не пишем всё на голом Python, потому что Flask берёт на себя:
  • разбор HTTP-запросов;
  • маршрутизацию (какой URL → какая функция);
  • работу с сессиями и cookie;
  • рендеринг HTML-шаблонов;
  • обработку ошибок.

0.4. Декораторы — что это за «собачка» @

Декоратор — это функция, которая «оборачивает» другую функцию, добавляя ей поведение. Запись @app.route('/test') над функцией означает: «зарегистрируй эту функцию как обработчик URL /test».
Когда Flask видит запрос на /test, он автоматически вызывает именно ту функцию, над которой стоит этот декоратор. Тебе не надо писать никаких if-ов.

0.5. Сессии и cookie — как сайт «помнит» пользователя

HTTP не хранит состояние: каждый запрос независим. Браузер не «помнит», что ты только что отвечал на вопрос. Чтобы помнить — используют cookie и сессии.
  • Cookie — маленький файл, который браузер хранит у себя и прикладывает к каждому запросу.
  • Сессия — это данные на сервере, но привязанные к конкретному пользователю через cookie-идентификатор.
Во Flask session — это словарь, который автоматически сохраняется в зашифрованную cookie.
Нам нужно помнить: какие ответы уже дал пользователь, какой вопрос сейчас показывать, сколько он набрал очков. Всё это храним в session.
Для работы session обязателен SECRET_KEY. Flask шифрует данные сессии, чтобы пользователь не мог их подделать.

0.6. SQLite и SQL — где хранятся вопросы

SQLite — встраиваемая база данных. Вся БД — один файл movies.sqlite. Не нужен отдельный сервер. SQL — язык запросов к базе. Основные команды: CREATE TABLE, INSERT, SELECT, DELETE.
База данных — это Excel-файл с несколькими листами (таблицами). SQL — способ сказать «дай мне такие-то строки».

0.7. Jinja2 — шаблонизатор

Jinja2 — движок шаблонов во Flask. Позволяет вставлять в HTML переменные и логику. Синтаксис:
  • {{ выражение }} — вывести значение
  • {% команда %} — цикл, условие, наследование
  • {# комментарий #} — комментарий
Мы не пишем HTML в строках Python (`return "

...

"`). Мы держим HTML в отдельном файле, а Flask подставляет в него данные. Это разделяет логику и представление.
Почему Jinja2 не может выполнять произвольный Python-код (например, open('file'))?
(Ответ: чтобы шаблон не мог случайно или намеренно сломать сервер. Jinja2 специально ограничивает возможности шаблонов.)

2 База данных — db_scripts.py

Что такое «схема БД»?
Это описание таблиц и связей между ними. У нас три таблицы:
  • quizzes — викторины (темы).
  • questions — вопросы.
  • answers — варианты ответов. У каждого — свой жанр.
Связь: один вопрос → много ответов (one-to-many).
Как оглавление книги: quizzes — разделы, questions — главы, answers — подпункты внутри главы.

2.1. Подключение к SQLite

Модуль sqlite3 — стандартный в Python, устанавливать не нужно. conn — соединение (канал связи). cursor — «рука», которой мы отправляем запросы и получаем строки.
# Импортируем встроенную библиотеку для работы с базой данных. # В Python она идёт "из коробки" — устанавливать ничего не надо. import sqlite3 # Имя файла базы данных. SQLite хранит всю БД в одном файле — # это очень удобно для учебных проектов. db_name = 'movies.sqlite' # Глобальные переменные для соединения и курсора. # Пока они пустые (None) — заполним их при открытии. conn = None cursor = None

2.2. Открытие, закрытие, выполнение запросов

Транзакция и commit. Изменения в БД не сохраняются мгновенно. Они накапливаются в «транзакции», и пока не вызван conn.commit(), они не записаны на диск. Если программа упадёт без commit — все изменения потеряются.
def open(): # global говорит: "я хочу изменить глобальные conn и cursor, # а не создавать локальные переменные внутри функции". global conn, cursor # Подключаемся к файлу БД. Если файла нет — SQLite создаст его сам. conn = sqlite3.connect(db_name) # Курсор нужен для отправки SQL-запросов. cursor = conn.cursor() def close(): # Аккуратно закрываем курсор и соединение. # Если не закрыть — данные могут не сохраниться. cursor.close() conn.close() def do(query): # Принимает SQL-строку, выполняет её и фиксирует изменения. cursor.execute(query) # commit() — это "сохранить изменения на диск". # Без него данные останутся в памяти и потеряются. conn.commit()
Оставлять соединение открытым. Если программа долго работает — соединение «протухает», и запросы начинают падать. Всегда закрывай через close().

2.3. Очистка старых таблиц

DROP TABLE IF EXISTS — команда, которая удаляет таблицу, если она есть. Если таблицы нет — не выдаёт ошибку. Без IF EXISTS запрос упадёт на первом запуске (таблицы ещё нет).
def clear_db(): ''' Удаляет все таблицы, если они есть ''' open() # DROP TABLE удаляет таблицу. # IF EXISTS — защита: если таблицы нет, ошибки не будет. do('DROP TABLE IF EXISTS answers') # сначала "дочерние" таблицы do('DROP TABLE IF EXISTS questions') do('DROP TABLE IF EXISTS quizzes') # потом "родительские" close()
Порядок важен: в answers есть внешний ключ на questions. Удалить родителя, пока на него ссылаются дети, база не даст.

2.4. Создание таблиц

PRIMARY KEY — уникальный идентификатор строки. По нему всегда можно найти строку. VARCHAR — тип «строка переменной длины». В SQLite, строго говоря, типы гибкие, но указывать их — хорошая практика. FOREIGN KEY — внешний ключ: ссылка на строку в другой таблице. Обеспечивает целостность данных.
def create(): open() # Включаем проверку внешних ключей. По умолчанию в SQLite они выключены! # Без этого FOREIGN KEY из таблицы answers работать не будет. do('PRAGMA foreign_keys = on') # Таблица "викторины" — список тем, которые выбирает пользователь. do('''CREATE TABLE IF NOT EXISTS quizzes ( id INTEGER PRIMARY KEY, -- уникальный номер викторины name VARCHAR, -- название description VARCHAR)''') -- краткое описание # Таблица "вопросы" — сами вопросы. do('''CREATE TABLE IF NOT EXISTS questions ( id INTEGER PRIMARY KEY, -- уникальный номер вопроса text VARCHAR)''') -- текст вопроса # Таблица "ответы" — варианты ответов. # Именно здесь хранится, к какому ЖАНРУ относится ответ. do('''CREATE TABLE IF NOT EXISTS answers ( id INTEGER PRIMARY KEY, question_id INTEGER, -- к какому вопросу относится text VARCHAR, -- текст кнопки genre VARCHAR, -- ЖАНР, к которому ведёт этот ответ FOREIGN KEY (question_id) REFERENCES questions (id))''') close()
Что произойдёт, если попытаться вставить в answers строку с question_id = 999, которого нет в questions?
(Ответ: SQLite откажет с ошибкой FOREIGN KEY constraint failed. Именно для этого нужен PRAGMA foreign_keys = on.)

2.5. Наполнение данными

executemany — выполняет один INSERT сразу для списка кортежей. Эффективнее, чем execute в цикле. Знаки ? — это «параметризованный запрос». SQLite сам подставит значения и защитит от SQL-инъекций.
Собирать SQL строкой: "INSERT INTO t VALUES ('" + value + "')". Если в value окажется кавычка или DROP TABLE — база разрушена. Никогда так не делай.
def add_quizzes(): # Список кортежей. Каждый кортеж = одна строка в таблице quizzes. # Порядок значений = порядок колонок в INSERT. quizzes = [ ('Подбор фильма на вечер', 'Ответь на 5 вопросов — получи жанр'), ('Что посмотреть с друзьями?', 'Комедия, боевик или что-то другое?'), ('Романтический вечер', 'Подберём фильм для двоих'), ] open() # executemany — вставляет сразу много строк за раз. # Знаки ? — это "заглушки". SQLite сам подставит значения # и защитит от SQL-инъекций (это важно для безопасности!). cursor.executemany( 'INSERT INTO quizzes (name, description) VALUES (?, ?)', quizzes) conn.commit() close()
def add_questions(): # Кортежи из одного элемента пишутся с запятой в конце: ('текст',) # Это не опечатка! Просто ('текст') — это строка, а ('текст',) — кортеж. questions = [ ('Какое у тебя сейчас настроение?',), ('С кем будешь смотреть?',), ('Сколько у тебя времени?',), ('Что важнее — сюжет или картинка?',), ('Хочешь ли ты посмеяться?',), ('Готов ли ты поплакать?',), ] open() cursor.executemany( 'INSERT INTO questions (text) VALUES (?)', questions) conn.commit() close()
def add_answers(): # Каждый ответ — это (question_id, текст_кнопки, жанр). # question_id связывает ответ с конкретным вопросом. # genre — это то, к чему "склоняет" ответ. answers = [ # Вопрос 1: настроение (1, 'Хочу приключений', 'adventure'), (1, 'Хочу подумать', 'drama'), (1, 'Хочу расслабиться', 'comedy'), (1, 'Хочу пощекотать нервы', 'thriller'), # Вопрос 2: с кем смотреть (2, 'Один', 'drama'), (2, 'С друзьями', 'comedy'), (2, 'С девушкой/парнем', 'romance'), (2, 'С семьёй', 'family'), # Вопрос 3: сколько времени (3, 'Меньше часа', 'short'), (3, '1–2 часа', 'standard'), (3, 'Хоть всю ночь', 'epic'), # Вопрос 4: что важнее (4, 'Сюжет', 'drama'), (4, 'Картинка', 'action'), # Вопрос 5: посмеяться? (5, 'Да', 'comedy'), (5, 'Нет', 'thriller'), # Вопрос 6: поплакать? (6, 'Да', 'drama'), (6, 'Нет', 'action'), ] open() cursor.executemany( 'INSERT INTO answers (question_id, text, genre) VALUES (?, ?, ?)', answers) conn.commit() close()
Логика подбора. Пользователь отвечает на вопросы. Каждый ответ добавляет «очко» одному из жанров. В конце побеждает жанр с наибольшим количеством очков — его и показываем.

2.6. Запросы для сайта

SELECT — читает данные. Можно указать конкретные поля, условия WHERE, сортировку ORDER BY. fetchall() — вернуть все строки как список кортежей. fetchone() — вернуть одну строку как кортеж.

ORDER BY answers.id ''' # В execute() передаём список значений для знаков ?. cursor.execute(query, [question_id]) # fetchall() — забрать ВСЕ строки ответа. result = cursor.fetchall() close() return result def first_question(): ''' Возвращает id первого вопроса (самый маленький) ''' open() cursor.execute('SELECT MIN(id) FROM questions') # fetchone() — забрать ОДНУ строку. Зачем мы в конце пишем result[0] if result else None, а не просто result[0]?
(Ответ: если в БД ничего нет, fetchone() вернёт None, и обращение к result[0] уронит программу с ошибкой. Мы защищаемся.)

2.7. Точка входа — main()

if __name__ == '__main__' — конструкция, которая проверяет: этот файл запущен напрямую или импортирован?
  • Запущен напрямую → __name__ == '__main__' → код выполнится.
  • Импортирован → __name__ == 'имя_модуля' → код НЕ выполнится.
Это позволяет использовать файл и как скрипт, и как модуль.

3.2. Стартовая страница

URL, начинающийся с /, — это корень сайта. Если сервер запущен на 127.0.0.1:5000, то / — это главная страница, а /test — вложенный путь.
# @app.route('/') — это декоратор. Он говорит Flask: # "Когда пользователь откроет главную страницу — вызови функцию index()". @app.route('/') def index(): # Очищаем "память" прошлой игры — начинаем заново. session['genre_scores'] = {} # очки по жанрам, пока пусто session['current_question'] = first_question() # id первого вопроса session['answered'] = 0 # сколько вопросов уже отвечено session['total'] = total_questions() # сколько всего вопросов # Показываем HTML-шаблон start.html return render_template('start.html')

3.3. Страница вопроса — сердце логики

Один маршрут — два метода. Когда пользователь открывает /test в браузере — это GET. Когда он нажимает кнопку в форме — это POST на тот же /test. Мы различаем их через request.method.
@app.route('/test', methods=['GET', 'POST']) def test(): # methods=['GET', 'POST'] — эта функция отвечает и на открытие страницы, # и на отправку формы. GET — показываем вопрос. POST — получаем ответ. # Защита: если сессии нет (пользователь зашёл напрямую на /test) — # отправляем его на главную. if 'genre_scores' not in session: return redirect(url_for('index')) # Если пришли данные из формы (нажата кнопка)... if request.method == 'POST': # ...достаём жанр из нажатой кнопки. # У кнопок в HTML было name="genre", value="comedy" — вот он. genre = request.form.get('genre') # Достаём текущие очки (или пустой словарь). scores = session.get('genre_scores', {}) # Прибавляем 1 к счётчику выбранного жанра. # .get(genre, 0) — если жанра ещё нет в словаре, берём 0. scores[genre] = scores.get(genre, 0) + 1 # Сохраняем обратно в сессию — иначе Flask не запомнит. session['genre_scores'] = scores # Увеличиваем счётчики: отвечено +1, следующий вопрос +1. session['answered'] = session.get('answered', 0) + 1 session['current_question'] = session.get('current_question', 1) + 1 # Проверяем: если все вопросы пройдены — уходим на результат. current_id = session.get('current_question') if session.get('answered', 0) >= session.get('total', 0): return redirect(url_for('result')) # Забираем данные следующего вопроса из БД. options = question_after(current_id) # Если для этого id нет вопросов — тоже к результату. if not options: return redirect(url_for('result')) # Первая строка результата — это текст вопроса (он одинаков во всех строках). question_text = options[0][1] # Убираем дубликаты вариантов. # Например, в вопросе 5 у нас ответы "Да"/"Нет", но может быть # два "Да" с разными жанрами — оставим по одному. seen = set() unique_options = [] for row in options: if row[2] not in seen: # row[2] — текст ответа seen.add(row[2]) unique_options.append({'text': row[2], 'genre': row[3]}) # Отдаём данные в шаблон test.html. return render_template( 'test.html', question=question_text, options=unique_options, progress=session.get('answered', 0), total=session.get('total', 0), )
Почему redirect, а не render_template? После POST-запроса, если просто отрисовать результат, при обновлении страницы (F5) браузер повторит POST. Redirect заставляет браузер сделать GET на результат — так надёжнее (это называется паттерн Post/Redirect/Get).

3.4. Страница результата

Функция max() с параметром key. max(scores, key=scores.get) находит в словаре ключ с максимальным значением. Работает это так: Python перебирает ключи, для каждого вызывает scores.get(key) и сравнивает результаты.
@app.route('/result') def result(): # Забираем очки из сессии. scores = session.get('genre_scores', {}) # Если очков нет — пользователь как-то попал сюда напрямую. # Отправляем на главную. if not scores: return redirect(url_for('index')) # Находим жанр с максимальным количеством очков. # max() с key=scores.get — "максимум по значению словаря". # Это вернёт КЛЮЧ (название жанра), а не число. winner = max(scores, key=scores.get) # Достаём справочники — красивое имя жанра и фильмы. genre_names = get_genre_names() movies = get_movies_by_genre() # Передаём всё в шаблон. return render_template( 'result.html', genre_name=genre_names.get(winner, winner), movies=movies.get(winner, []), # Формируем словарь "красивое имя" -> очки для отображения. scores={genre_names.get(k, k): v for k, v in scores.items()}, )

3.5. Перезапуск и запуск

@app.route('/restart') def restart(): # Просто очищаем всю сессию — как будто пользователь зашёл впервые. session.clear() # И отправляем его на главную. return redirect(url_for('index')) # Эта часть выполнится, только если запустить файл напрямую: # python app.py # debug=True включает авто-перезагрузку при изменении кода # и подробные ошибки в браузере. В продакшене так НЕ делают. if __name__ == '__main__': app.run(debug=True)
✅ Проверь: запусти python app.py, открой http://127.0.0.1:5000. Если видишь «TemplateNotFound» — это нормально! Мы ещё не сделали шаблоны. Идём в шаг 4.

4 HTML-шаблоны (Jinja2)

Зачем шаблоны?
Можно было бы писать return "

Привет

" из Flask. Но:
  • HTML будет огромным — неудобно;
  • смешивается логика и вёрстка;
  • нельзя переиспользовать куски.
Шаблонизатор Jinja2 решает всё это: HTML остаётся в .html-файле, а данные подставляются через {{ }}.

4.1. start.html

<!DOCTYPE html> <html lang="ru"> <head> <meta charset="UTF-8"> <!-- url_for('static', filename='...') — правильный способ подключить CSS из папки static. Flask сам построит нужный путь. --> <link rel="stylesheet" href="{{ url_for('static', filename='style_quiz.css') }}"> <title>Киноподборщик</title> </head> <body> <div class="card"> <h1>🎬 Подбор фильма на вечер</h1> <p class="subtitle">Ответь на вопросы — и мы подберём идеальный фильм.</p> <!-- url_for('test') строит ссылку на функцию test() в app.py. Если маршрут поменяется — ссылка автоматически обновится. --> <a href="{{ url_for('test') }}" class="btn">Начать подбор →</a> <!-- session доступна в шаблонах Flask автоматически. Здесь выводим, сколько всего вопросов (число из app.py). --> <p class="hint">Всего вопросов: {{ session.get('total', '?') }}</p> </div> </body> </html>

4.2. test.html

Форма и метод POST. Атрибут method="POST" говорит браузеру: «отправь данные в теле запроса». Атрибут action — куда отправлять. Обычно это тот же URL.
<!DOCTYPE html> <html lang="ru"> <head> <meta charset="UTF-8"> <link rel="stylesheet" href="{{ url_for('static', filename='style_quiz.css') }}"> <title>Вопрос</title> </head> <body> <div class="card"> <!-- progress и total мы передали из app.py в render_template --> <div class="progress">Вопрос {{ progress + 1 }} из {{ total }}</div> <!-- Текст текущего вопроса --> <h2>{{ question }}</h2> <!-- Форма отправляет POST-запрос на тот же /test. Атрибут method="POST" — обязательно, иначе данные не дойдут. --> <form method="POST" action="{{ url_for('test') }}"> <!-- Цикл по всем вариантам ответа. options — это список словарей вида {'text': ..., 'genre': ...}. --> {% for opt in options %} <button type="submit" name="genre" value="{{ opt.genre }}" class="option"> {{ opt.text }} </button> {% endfor %} <!-- Итог: в app.py request.form.get('genre') получит именно значение value нажатой кнопки. Вот как это работает! --> </form> <div class="score-hint">Прогресс: {{ progress }} / {{ total }}</div> </div> </body> </html>
Что будет, если убрать name="genre" у кнопки?
(Ответ: Flask не получит данные — request.form.get('genre') вернёт None, и в scores запишется мусор.)

5 CSS — оформление

CSS — Cascading Style Sheets — язык оформления. Селектор (например, .card) задаёт, к каким элементам применить правила, а фигурные скобки содержат сами свойства.
* { box-sizing: border-box; margin: 0; padding: 0; } /* box-sizing: border-box — чтобы padding и border входили в width. Без него ширины считаются неинтуитивно. */ body { font-family: system-ui, -apple-system, sans-serif; /* Градиентный фон — смотрится современно и не требует картинок */ background: linear-gradient(135deg, #1a1a2e, #16213e); min-height: 100vh; /* Flexbox: центрируем карточку по горизонтали и вертикали */ display: flex; align-items: center; justify-content: center; color: #eaeaea; padding: 20px; } /* .card — "карточка" с контентом. Один универсальный контейнер на все страницы. */ .card { background: #0f3460; border-radius: 16px; padding: 40px; max-width: 600px; width: 100%; /* Тень делает карточку "объёмной" */ box-shadow: 0 20px 60px rgba(0, 0, 0, 0.5); } h1 { color: #e94560; margin-bottom: 12px; } h2 { margin: 20px 0; font-size: 1.4rem; } h3 { margin: 20px 0 10px; color: #9aa9c2; font-size: 1rem; } .subtitle { color: #9aa9c2; margin-bottom: 24px; } /* Кнопки "Начать" и "Пройти заново" */ .btn { display: inline-block; margin-top: 24px; padding: 14px 32px; background: #e94560; color: #fff; border: none; border-radius: 10px; font-size: 1rem; font-weight: 700; text-decoration: none; cursor: pointer; transition: 0.2s; } .btn:hover { background: #ff5a75; transform: translateY(-2px); } /* Кнопки-варианты ответа. width: 100% — чтобы каждая занимала всю ширину карточки. */ .option { display: block; width: 100%; margin: 10px 0; padding: 16px 20px; background: #16213e; border: 2px solid #0f3460; border-radius: 10px; color: #eaeaea; font-size: 1rem; text-align: left; /* чтобы текст не центрировался */ cursor: pointer; transition: 0.2s; } .option:hover { border-color: #e94560; background: #1a2a4a; /* Лёгкий сдвиг вправо при наведении — "живой" эффект */ transform: translateX(4px); } .progress { color: #9aa9c2; font-size: 0.9rem; margin-bottom: 10px; text-transform: uppercase; letter-spacing: 2px; } .score-hint { margin-top: 20px; color: #9aa9c2; font-size: 0.85rem; text-align: right; } .genre { color: #e94560; font-size: 2rem; } /* Список фильмов и очков */ .movies li, .scores li { margin: 8px 0; padding: 8px 12px; background: rgba(255, 255, 255, 0.05); border-radius: 6px; list-style: none; /* убираем стандартные точки списка */ } .hint { margin-top: 16px; color: #9aa9c2; font-size: 0.85rem; }
CSS не влияет на логику — только на внешний вид. Но именно он превращает голый HTML в приятный сайт.

6 Запуск и отладка

  1. Первый раз — python db_scripts.py (создать БД).
  2. Потом — python app.py (запустить сайт).
  3. Открыть http://127.0.0.1:5000.
db_scripts.py — это строители: один раз построили склад. app.py — это продавец: работает каждый день и берёт товар со склада.
⚠ Если что-то не работает — ищи причину по симптому:
  • «no such table» — не запущен db_scripts.py.
  • «TemplateNotFound» — файл шаблона лежит не в templates/ или опечатка в имени.
  • Пустая страница — забыл {{ }} вокруг переменной.
  • Session не работает — не задан SECRET_KEY.
  • Форма не отправляется — забыл method="POST" или name="genre".
  • Результат не тот — проверь, что у кнопок в шаблоне value="{{ opt.genre }}", а не {{ opt.text }}.
